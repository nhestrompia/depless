# DepLess

DepLess is an agent skill for reviewing JavaScript and TypeScript dependencies. Its read-only audit inventories direct packages in a project or basic workspace, reports configured targets, shows usage evidence, and recommends which packages to remove, replace, keep, or review. Prevent mode assesses a proposed new package before installation.

## Install

After the repository is published, install the `depless` skill with an Agent Skills-compatible coding agent:

```sh
npx skills add nhestrompia/depless --skill depless
```

You can also copy `skills/depless` into your agent's project skill directory. The folder contains the Agent Skills `SKILL.md` file. Project-local copies were exercised with Codex at `.agents/skills/depless` and OpenCode at `.opencode/skills/depless`.

## Use

Ask your agent, "Use DepLess to audit this project's dependencies." It will read the selected `package.json` and return the dependency inventory in the conversation. A basic audit does not edit the project or run package scripts.

For prevent mode, ask, "Use DepLess to evaluate whether this project should add `<package>` for `<capability>`." The agent will compare alternatives and return advice without installing anything.

After reviewing an audit proposal, you can ask the agent to apply a specific replacement. Supported examples include a Node.js-only `uuid` v4 call using `randomUUID` from `node:crypto`, compatible `clsx` calls using the classnames registry item, and trailing-only Lodash `debounce` use with pending cancel or flush. The agent should run relevant checks before and after package removal and report the measured change.

## Registry source

The registry currently has [classNames](registry/strings/classnames/README.md), [debounce](registry/timing/debounce/README.md), [throttle](registry/timing/throttle/README.md), [groupBy](registry/collections/group-by/README.md), and [uniqueBy](registry/collections/unique/README.md). Review each item's behavior and tests before copying source into a project. Registry source has no runtime package dependencies.

The root `registry.json` builds the tracked `public/r` distribution. After an approved commit is published, set `sha` to its full 40-character SHA, inspect the JSON and source at that revision, and preview the pinned item before installing it:

```sh
sha=FULL_40_CHARACTER_COMMIT_SHA
npx shadcn@4.20.0 add "https://raw.githubusercontent.com/nhestrompia/depless/${sha}/public/r/classnames.json" --dry-run --diff
npx shadcn@4.20.0 add "https://raw.githubusercontent.com/nhestrompia/depless/${sha}/public/r/classnames.json"
```

The item targets the consumer's configured `lib` alias and adds a copy of the MIT license. Its raw source is `https://raw.githubusercontent.com/nhestrompia/depless/FULL_40_CHARACTER_COMMIT_SHA/registry/strings/classnames/index.ts` after replacing the placeholder.

## Compatibility and checks

The skill targets JavaScript and TypeScript projects using npm or pnpm, with basic workspace support. Bun projects are considered when targets are declared; Yarn is best effort. Registry behavior is tested on Node.js 24. Browser and Bun runtimes are intended targets but have not been run in CI. React Native, Expo, Deno, and Cloudflare Workers need separate compatibility work. Audit recommendations depend on the files and configuration available to the agent; unknown targets and indirect package use should stay under review.

Run `npm ci`, `npm run typecheck`, `npm test`, and `npm run validate:registry` to check the local source and tracked installable items. CI also rebuilds `public/r` with shadcn 4.20.0 and compares every generated byte with the tracked distribution. The [MVP compatibility notes](tests/mvp-compatibility.md) list the sample agent and consumer checks. Test the skill against your own projects before relying on a replacement recommendation.
